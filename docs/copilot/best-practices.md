# VS CodeでAIを使用するためのベストプラクティス

この記事では、Visual Studio CodeでAIを使用する際の実証されたプラクティスについて説明します。各セクションでは、実行可能なガイダンスと詳細なドキュメントへのリンクを提供します。

## AIのためのプロジェクトを最適化する

AIを念頭に置いてプロジェクトとコードベースを設定することで、AI応答の精度を向上させ、AIがチームのコーディング標準とプラクティスに従うようにできます。

VS Codeは、プロジェクトのAI動作を設定するためのいくつかのメカニズムをサポートしています。チャットで`/init`を入力して、スターター設定を生成します。

| メカニズム | 最適な用途 | はじめへ |
|-----------|----------|-------------|
| [カスタム指示](/docs/copilot/customization/custom-instructions.md) | プロジェクト全体のコーディング標準とアーキテクチャコンテキスト | `/init`を入力してベースファイルを生成 |
| [プロンプトファイル](/docs/copilot/customization/prompt-files.md) | 繰り返しタスク用の再利用可能なプロンプト（レビュー、スキャフォールディング） | `/prompts`を入力して管理 |
| [カスタムエージェント](/docs/copilot/customization/custom-agents.md) | 特殊なワークフローまたはペルソナ（TDD、セキュリティ監査） | `/agents`を入力して管理 |
| [エージェントスキル](/docs/copilot/customization/agent-skills.md) | ドメイン固有の機能（テスト、デプロイ） | `/skills`を入力して管理 |
| [ツールおよびMCPサーバー](/docs/copilot/agents/agent-tools.md) | 外部システムへの接続（データベース、API、CLI） | `mcp.json`で設定 |

効果的なプロジェクト設定のコツ：

* **指示ファイルは簡潔に保つ。** チャトの相互作用のたびに読み込まれます。AIがコードから推測できない情報（デフォルト以外の規則、アーキテクチャ決定、環境セットアップなど）に焦点を当てます。
* **`applyTo`パターンで指示を範囲化する。** `/instructions`を入力して、すべてを1つのファイルに含める代わりに、言語固有またはフォルダ固有の指示ファイルを作成します。
* **有効なツールを制限する。** アクティブなツールが少ないほど、応答がより高速で関連性が高くなります。タスクで必要な場合のみツールを有効にします。

完全なセットアップの詳細については、[カスタマイズの概要](/docs/copilot/customization/overview.md)を参照してください。

## タスクに最適なツールを選択する

VS CodeのAIは複数の相互作用モードを提供します。タスクに適したモードを選択することで、時間を節約し、より良い結果が得られます。

| ツール | 最適な用途 | 例 |
|------|----------|---------|
| [インライン提案](/docs/copilot/ai-powered-suggestions.md) | コード作成中の流れの中にいること | コード補完、変数名、ボイラープレート |
| [質問（チャット）](/docs/copilot/chat/copilot-chat.md) | 質問、ブレーンストーミング、アイデア探索 | 「このプロジェクトの認証はどのように機能しますか？」 |
| [インラインチャット](/docs/copilot/chat/inline-chat.md) | コンテキストを切り替えることなく対象の編集をその場で実施 | 関数をリファクタリング、エラーハンドリングを追加 |
| [エージェント](/docs/copilot/agents/overview.md) | 自律的な計画とツール使用が必要なマルチファイル変更 | エンドツーエンドで機能を実装 |
| [計画](/docs/copilot/agents/planning.md) | 実装前の構造化計画 | アーキテクチャまたは移行戦略の設計 |
| [スマートアクション](/docs/copilot/copilot-smart-actions.md) | 組み込みの特殊な1ステップタスク | コミットメッセージの生成、エラーの修正、シンボルの名前変更 |

## 効果的なプロンプトを作成する

AI応答の品質は、プロンプトの明確さと具体性に依存します。これらのテクニックは、より良い結果を得るのに役立ちます。

* **入力、出力、制約について具体的に説明する。** 使用したいプログラミング言語、フレームワーク、ライブラリを述べます。予期される動作を説明するか、入力と出力の例を含めます。

    ```prompt
    メールアドレスを検証するTypeScript関数を作成します。
    有効なアドレスの場合はtrueを返し、そうでない場合はfalseを返します。正規表現を使用しないでください。
    例：validateEmail("user@example.com")はtrueを返します
    例：validateEmail("invalid")はfalseを返します
    ```

* **複雑なタスクを分解する。** 機能全体を一度に求める代わりに、より小さく、適切にスコープされたステップに分解します。このアプローチはより信頼性の高い結果を生成し、問題を早期に検出しやすくします。

* **検証のための予期される出力を含める。** AIが独自の作業を検証できるように、テストケース、予期される結果、または受け入れ基準を提供します。このステップは最も高いレバレッジを持つことができるものの1つです。

    ```prompt
    トークンバケットアルゴリズムを使用してレート制限ツールを実装します。
    次を検証する単体テストを作成します：10リクエスト/秒が許可され、
    11番目のリクエストは拒否され、バケットは1秒後に再補充されます。
    実装後にテストを実行します。
    ```

* **曖昧なプロンプトを避ける。** 「これをより良く」というプロンプトはAIに方向を示しません。代わりに「より良い」の意味を明確にします：「時間計算量を削減」または「null値の入力検証を追加」。

* **後続プロンプトで繰り返す。** プロンプト全体を書き直すのではなく、後続メッセージで制約または修正を追加して応答を改善します。

* **早期に調整する。** AIが間違った方向に向かている場合は、後続メッセージで[それを導く](/docs/copilot/chat/chat-sessions.md#send-messages-while-a-request-is-running)ことで、現在のリクエストをリダイレクトするか、後続リクエストをキューにいれるか、停止して新しいプロンプトを送信します。

* **AIに澄ましの質問をするよう指示する。** タスクが曖昧な場合、AIに進める前に質問をするよう指示します。これは要件を推測するよりも正確な結果につながります。

* **並列タスク。** 複数の独立したタスクがある場合、AIに時間を節約するためにそれらを並列実行するよう求めます。例えば、「XとYについて分離した調査を並列実行し、結果を要約してください」。

詳細については、[プロンプトエンジニアリング](/docs/copilot/guides/prompt-engineering-guide.md)と、GitHub Copilotドキュメント内の実践的な[プロンプト例](https://docs.github.com/en/copilot/copilot-chat-cookbook)を参照してください。

## 適切なコンテキストを提供する

AIは関連するコンテキストがある場合、より正確に応答します。AIを正しい情報に向けるには、これらのテクニックを使用します：

* AIは関連するコンテキストを収集するためにコード検索を自動的に実行します。プロンプトが曖昧な場合、`#<file>`、`#<folder>`、または`#<symbol>`でプロンプト内の特定のファイル、フォルダ、またはシンボルを参照することでAIをガイドできます。

* Webページまたはgithubリポジトリから情報を取得するには、`#fetch`または`#githubRepo`を使用して、コードベース以上の最新情報をAIに提供します。

* ソースコントロールの変更、ターミナル出力、テスト失敗などのVS Code環境コンテキストを参照して、AIがプロジェクトの現在の状態を理解し、より関連性の高い応答を提供するのを支援します。

* AIが視覚的なコンテンツを分析できるように、画像またはスクリーンショットを追加します。

* [統合ブラウザ](/docs/debugtest/integrated-browser.md)を使用してアプリをプレビューし、ページ要素を選択してコンテキストとして使用します。

詳細については、[チャットプロンプトにコンテキストを追加する](/docs/copilot/chat/copilot-chat-context.md)と[ツールを設定する](/docs/copilot/agents/agent-tools.md)を参照してください。

## 適切なモデルを選択する

各AIモデルには異なる強度があります。推論に優れたものもあり、コード生成または高速応答に優れたものもあります。タスクに適したモデルを選択することで結果が向上します。

* **モデルをタスク複雑さと照合する。** 単純な補完とボイラープレートには高速モデルを使用します。計画、デバッグ、またはアーキテクチャ決定には、推論最適化モデルに切り替えます。

* **最新モデルを使用する。** 新しいモデルには、しばしば改善された機能があります。VS Codeは新しいモデルとモデルバージョンのサポートを継続的に追加します。[利用可能なモデル](/docs/copilot/customization/language-models.md)を確認し、最新モデルを使用します。

* **プロンプトファイルとエージェントでモデルをピンする。** プロンプトファイルまたはカスタムエージェント定義で優先モデルを指定して、特定のタスクに対して正しいモデルが一貫して使用されるようにします。

* **実験と比較。** 応答に満足していない場合は、別のモデルを試してください。異なるモデルは同じプロンプトに対して大きく異なる結果を生成できます。

* **追加の制御にはBYOKを使用する。** 独自のAPIキーを持参して、より多くのモデル選択肢とホスティングオプションを利用できます。

詳細については、[AIモデルの選択](/docs/copilot/customization/language-models.md)と[Copilot Chatで利用可能なモデル](https://docs.github.com/en/copilot/using-github-copilot/ai-models/changing-the-ai-model-for-copilot-chat)を参照してください。

## 最初に計画してから実装する

複数のファイルにまたがる複雑な変更の場合は、計画と実装を分離します。このアプローチにより、AIが間違った問題を解決するのを防ぐことができます。

1. **探索。** Ask モードまたはサブエージェントを使用して、関連するコードを読み、変更を行う前にそれがどのように機能するかを理解します。
1. **計画。** [計画エージェント](/docs/copilot/agents/planning.md)を使用して、構造化された実装計画を作成します。実行前に計画を確認して改善します。
1. **実装。** エージェントモードに切り替えて、計画から実装します。エージェント自身の作業を検証できるように、テストまたは予期される出力を含めます。長いタスクは[バックグラウンドエージェント](/docs/copilot/agents/copilot-cli.md)または[クラウドエージェント](/docs/copilot/agents/cloud-agents.md)に引き継ぎます。
1. **確認。** [チェックポイント](/docs/copilot/chat/chat-checkpoints.md)を使用して進行状況を確認し、エージェントが軌道を外れた場合は巻き戻すか、結果のプルリクエストで[Copilotコード確認をリクエスト](https://docs.github.com/en/copilot/concepts/agents/code-review)します。

詳細については、[コンテキストエンジニアリングワークフロー](/docs/copilot/guides/context-engineering-guide.md)を参照してください。

## AIの出力を確認して検証する

AI生成コードはバグ、セキュリティの問題、または微妙なロジックエラーを含むことができます。AIの出力は常に確認が必要な出発点として扱います。

* **受け入れる前に確認する。** 生成されたコードを受け入れる前に読み込みます。AIが行ったエッジケース、エラーハンドリング、および仮定に注意を払います。

* **AI変更後にテストを実行する。** AIが独自の作業を検証できるように、プロンプトにテストケースを含めます。AIがテストを自動的に実行しない場合は、先に進む前にテストを自身で実行します。

* **チェックポイントを使用して巻き戻す。** エージェントが軌道を外れた場合は、[チェックポイント](/docs/copilot/chat/chat-checkpoints.md)を使用して、連鎖エラーの修正を試みるのではなく、既知の良い状態に戻します。

* **セキュリティの問題を確認する。** AI生成コードで、注入欠陥、ハードコードされたシークレット、または欠落している入力検証などの一般的な脆弱性を確認します。プロンプトに認証情報または機密データを貼り付けることは避けます。

詳細については、[GitHub Copilotセキュリティ](/docs/copilot/security.md)と[GitHub Copilot Trust Center](https://copilot.github.trust.page/faq)を参照してください。

## コンテキストとセッション管理する

会話が無関係なコンテキストで満たされると、AI応答が低下する可能性があります。セッションをプロアクティブに管理します。

* **無関係なタスクのための新しいセッションを開始する。** 無関係な質問を1つの会話に積み重ねないでください。コンテキスト汚染は応答品質を低下させます。

* **無関係な履歴を削除する。** 不適切に関連するもう不要となった過去の質問と応答を削除するか、新しいセッションを開始します。

* **調査にはサブエージェント使用。** [サブエージェント](/docs/copilot/agents/subagents.md)を使用することで研究と探索を分離で実行するようAIに指示し、調査結果がメインコンテキストを混乱させないようにします。

* **正しいセッションタイプを選択する。** ローカルセッションを現在のコードで修正が必要な高速タスクに使用し、バックグラウンドタスクはメインコンテキストから分離してローカルで実行できるタスクに、またはクラウドセッションはチーム協力から利益を受けることができるセッションに使用します。

* **並列セッションでスケール。** 独立したタスクのために複数のセッションを並列実行して、時間を節約し、コンテキストを分離します。一度に複数のセッションをローカル、バックグラウンド、クラウド環境全体で実行でき、VS Codeの[エージェントセッション表示](/docs/copilot/agents/overview.md#agent-sessions-list)経由でそれらを切り替えることができます。

詳細については、[セッション管理](/docs/copilot/chat/chat-sessions.md)と[ワークスペースインデックス](/docs/copilot/reference/workspace-context.md)を参照してください。

## 大規模なコードベースで作業する

Copilotは大規模で複雑なマルチルートワークスペースで効果的に作業するように設計されています。大規模でインテリジェントな結果を得るには、これらのプラクティスを使用します。

* **ワークスペースインデックスを使用する。** VS Codeはセマンティック検索、言語インテリジェンス、およびgithubのコード検索を使用してプロジェクトを自動的にインデックスし、深いクロスファイル推論を行います。これは小規模プロジェクトと大規模エンタープライズコードベースの両方で機能します。大規模なリポジトリの場合、リポジトリおよび関連する github リポジトリ全体で高速で包括的な結果を得るために、[リモートインデックス](/docs/copilot/reference/workspace-context.md#remote-index)を使用します。

* **マルチルートワークスペースで作業を範囲化する。** モノレポまたは複数のサービスを含むプロジェクトの場合、[マルチルートワークスペース](/docs/editing/workspaces/multi-root-workspaces.md)を使用して、AIに明確な範囲と焦点を絞ったコンテキストを提供します。

* **プロジェクトレベルの指示を提供する。** [カスタム指示](/docs/copilot/customization/custom-instructions.md)を使用して、プロジェクトのアーキテクチャ、モジュール境界、およびAIがコードだけからは推測できないコンベンションを説明します。これはアーキテクチャレベルの変更に必要なコンテキストをAIに与えます。

* **独立する変更に対して並列セッションを実行する。** 大規模なタスクを独立したサブタスクに分割し、コードベースの異なる領域に焦点を当てた[並列エージェントセッション](/docs/copilot/agents/overview.md#agent-sessions-list)で実行します。

* **クロスカッティング変更には計画エージェントを使用する。** 多くのファイルまたはモジュールにまたがる変更の場合、実行前に[計画エージェント](/docs/copilot/agents/planning.md)を使用して、構造化された実装計画を作成します。

詳細については、[ワークスペースコンテキスト](/docs/copilot/reference/workspace-context.md)と[エージェント](/docs/copilot/agents/overview.md)を参照してください。
