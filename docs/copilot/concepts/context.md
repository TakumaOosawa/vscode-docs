# コンテキスト

コンテキストは、モデルが応答を生成する際に見ることができるすべてのものです。会話履歴、ワークスペース内のファイル内容、ツール出力、カスタム指示、明示的に追加した参照が含まれます。モデルは見ることができるもの以外について推論することはできないため、関連するコンテキストを提供することが AI 応答を改善する最も効果的な方法の一つです。

この記事では、VS Code がコンテキストを構築する方法、利用可能なコンテキストの種類、コンテキストウィンドウの制限に効果的に対処する方法について説明します。

## コンテキストが重要な理由

関連ファイル、明確な指示、焦点を絞った履歴を含むプロンプトは、コンテキストなしの曖昧なプロンプトより優れた結果をもたらします。モデルは前のセッションの記憶がなく、提供されていないファイルへのアクセス権がありません。タスクについて知っているすべてのことは、現在のリクエスト用に組み立てられたコンテキストから来ています。

## VS Code がコンテキストを構築する方法

メッセージを送信すると、VS Code は複数のソースから言語モデルプロンプトを構築します:

![コンテキストウィンドウをシステム指示、カスタマイズ、ユーザーメッセージ、会話履歴、暗黙的なコンテキスト、明示的な参照、ツール出力の7つのレイヤーを持つコンテナとして示す図。組み立てられたプロンプトを言語モデルに送信する矢印があります。](../images/concepts/context-assembly.png)

* **システム指示**: エージェントの動作を定義する組み込みガイドライン。
* **カスタマイズ**: カスタムエージェント、スキル、カスタム指示を含む AI カスタマイズ。
* **ユーザーメッセージ**: エージェントに送信している現在のメッセージ。
* **会話履歴**: 現在のセッションでこれまでにやり取りされたメッセージ。
* **暗黙的なコンテキスト**: 編集中のファイル、現在の選択、表示されているエラー、git 状態。
* **明示的な参照**: `#`-mentions で参照するファイル、エディターコンテキスト、web コンテンツ、その他のソース。
* **ツール出力**: ファイルの読み取り、ターミナルコマンド、コードベース検索結果、エージェントセッション中のその他のツール呼び出しの結果。

この組み立てられたプロンプトはモデルが見るものです。その外側のすべてはモデルには見えません。これが、`#file`でファイルを参照すると、モデルが見ていないコードについて質問するより優れた結果が得られる理由です。

## ワークスペースインデックス

VS Code はインデックスを使用して、コードベースから関連するコードスニペットを迅速かつ正確に検索します。このインデックスは GitHub で管理することも、マシンにローカルに保存することもできます。

* **リモートインデックス**: コードが GitHub リポジトリでホストされている場合、リモートインデックスを構築して、大規模なコードベースであっても素早くコードベースを検索できます。
* **ローカルインデックス**: マシンに格納された高度なセマンティックインデックスを使用して、高速で正確な検索結果を実現します。
* **基本インデックス**: ローカルインデックスが利用できない場合、より単純なアルゴリズムがより大きなコードベース用にローカルで機能します。

[ワークスペースインデックス](/docs/copilot/reference/workspace-context.md)の詳細をご覧ください。

## 暗黙的なコンテキスト

VS Code は、現在のアクティビティ に基づいてプロンプトにコンテキストを自動的に提供します:

* アクティブエディターで現在選択されているテキスト。
* アクティブエディターのファイル名またはノートブック名。
* **Ask** エージェントを使用している場合、アクティブファイルが自動的にコンテキストとして含まれます。
* **Agent** を使用する場合、プロンプトに基づいてアクティブファイルを追加する必要があるかどうかを自律的に決定します。

## コンテキストを効果的に使用する

* **新しいタスク用に新しいセッションを開始します。** [セッション](/docs/copilot/chat/chat-sessions.md)は独立した会話で、独自のコンテキストウィンドウと履歴を持ちます。各セッションは新しく開始されるため、関連のない複数のタスク用に1つの会話を再利用しないでください。
* **コンテキストを選択的に使用します。** コードベース全体を追加することが常に有益とは限りません。タスクに関連する特定のファイルを参照してください。
* **永続的なルール用にカスタム指示を使用します。** [カスタム指示](/docs/copilot/customization/custom-instructions.md)に追加したルールはすべてのリクエストに含まれるため、会話が要約されるときに失われません。

### 例

次の例は、コンテキストを追加することで結果がどのように改善されるかを示しています:

**曖昧なプロンプト(コンテキストなし)**:

```prompt
認証はどのように機能しますか?
```

モデルは、どのプロジェクトを意味するのか知る方法がなく、認証パターンについての一般的な回答を与えます。

**明示的なコンテキスト付きプロンプト**:

```prompt
このプロジェクトでは認証はどのように機能しますか?
```

モデルは実装した認証ファイルを読み、特定の関数と構成値を参照してあなたの実装がどのように機能するかを説明します。

**web コンテキスト付きプロンプト**:

```prompt
auth モジュールを最新の passport.js API に移行します #fetch https://www.passportjs.org/concepts/authentication/
```

モデルは web の現在のドキュメントを使用して移行をガイドし、トレーニングデータから廃止された API パターンを回避します。

[チャットにコンテキストを追加する](/docs/copilot/chat/copilot-chat-context.md)の詳細をご覧ください。
