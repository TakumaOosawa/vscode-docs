# VS Codeでのプロンプトエンジニアリング

この記事では、Visual Studio CodeのAIからより適切で関連性の高い応答を得るためのプロンプト作成のヒントを取り上げます。_プロンプトエンジニアリング_または_プロンプトクラフティング_は、AIについて議論する際によく耳にする言葉であり、情報がどのようにパッケージ化され、AI APIエンドポイントに送信されるかを指します。

VS CodeやAIを初めて使用する場合は、最初に[VS CodeでのAIの概要](/docs/copilot/overview.md)記事を確認するか、[入門](/docs/copilot/getting-started.md)チュートリアルに直接進むことをお勧めします。

## インライン候補を最大限に活用する

インライン候補は、コード、コメント、テストなどを補完するための提案を自動的に提供することで、より効率的にコーディングできるように支援します。AIが可能な限り最良の提案を行えるように支援（「プロンプト」）するためにできることがあります。

### コンテキストを提供する

AIは、ユーザーが何をしていて、何について助けを求めているかを知るための十分なコンテキストがある場合に最もよく機能します。特定のプログラミングタスクの助けを求めるときに同僚にコンテキストを提供するのと同じように、AIに対しても同じことができます。

#### ファイルを開く

インライン候補の場合、VS Codeはエディター内の現在および開いているファイルを調べてコンテキストを分析し、適切な提案を作成します。インライン候補を使用しているときにVS Codeで関連ファイルを開いておくと、このコンテキストを設定するのに役立ち、AIがプロジェクトの全体像を把握できるようになります。

#### トップレベルのコメント

同僚に簡潔で高レベルの紹介をするのと同じように、作業中のファイルのトップレベルのコメントは、作成している部分の全体的なコンテキストをAIが理解するのに役立ちます。

#### 適切なインクルードと参照

作業に必要なインクルードやモジュール参照は手動で設定するのが最適です。AIは提案を行うことができますが、どの依存関係を含める必要があるかは、おそらくあなたが一番よく知っています。これは、AIが提案を作成する際に使用してほしいフレームワーク、ライブラリ、およびそれらのバージョンをAIに知らせるのにも役立ちます。

次のTypeScriptの例では、`add`メソッドの出力をログに記録したいと考えています。インクルードがない場合、AIは`console.log`の使用を提案します。

![ファイルにインポートがない場合にAIインライン候補がConsole.logを提案する様子。](../images/prompt-engineering-guide/copilot-suggestion-console-log.png)
一方、`Log4js`への参照を追加すると、AIはそのフレームワークを使用して出力をログに記録することを提案します。

![インポートされたログフレームワークを使用したログ記録をAIインライン候補が提案する様子。](../images/prompt-engineering-guide/copilot-suggestion-framework-log.png)

#### 意味のある関数名

`fetchData()`というメソッドが同僚（あるいは数か月後のあなた）にとってあまり意味がないのと同じように、`fetchData()`はAIにとっても役に立ちません。意味のある関数名を使用すると、AIがあなたが望むことを行う本体を提供するのに役立ちます。

#### 具体的で範囲が明確な関数のコメント

関数名は、長くなりすぎずに説明できる範囲に限りがあります。関数のコメントは、AIが知る必要のある詳細を補完するのに役立ちます。

#### サンプルコードでAIを準備する

AIに正しい認識を持たせるための1つのコツは、探しているものに近いサンプルコードをコピーして開いているエディターに貼り付けることです。小さな例を提供することで、AIが達成したい言語やタスクに一致する提案を生成するのに役立ちます。AIがあなたが望み、実際に使用するコードを提供し始めたら、ファイルからサンプルコードを削除できます。これは、AIが古いコードの提案をデフォルトで提供する場合に、新しいライブラリバージョンへAIを誘導するのに特に役立ちます。

### 一貫性を保ち、品質基準を高く維持する

AIは既存のパターンに従った提案を生成するためにあなたのコードに追随するため、「ゴミを入れればゴミが出てくる（Garbage In, Garbage Out）」という格言が当てはまります。
常に高い品質基準を維持するには規律が必要です。特に、何かを動作させるために急いで大まかなコーディングをしている場合、「ハッキング」モードの間は補完を無効にしたくなるかもしれません。インライン候補を一時的にスヌーズするには、ステータスバーのCopilotメニューを選択し、**Snooze**ボタンを選択してスヌーズ時間を5分ずつ延長します。インライン候補を再開するには、Copilotメニューの**Cancel Snooze**ボタンを選択します。

![SnoozeボタンとCancel SnoozeボタンがあるステータスバーのCopilotメニューのスクリーンショット。](../images/inline-suggestions/snooze-code-completions.png)

## チャットを最大限に活用する

チャットを使用する場合、エクスペリエンスを最適化するためにできることがいくつかあります。

### 関連するコンテキストを追加する

プロンプトに`#`と入力し、その後に言及したいコンテキスト項目を続けることで、コンテキストを明示的に追加できます。VS Codeは、ファイル、フォルダー、コードシンボル、ツール、ターミナル出力、ソース管理の変更など、さまざまな種類のコンテキスト項目をサポートしています。

チャット入力フィールドに`#`記号を入力して利用可能なコンテキスト項目の一覧を表示するか、チャットビューで**Add Context**を選択してコンテキストピッカーを開きます。

たとえば、`#<file name>`または`#<folder name>`を使用すると、ワークスペース内の特定のファイルまたはフォルダーをチャットプロンプトで参照できます。これにより、作業中のファイルに関するコンテキストが提供されるため、Copilot Chatからの回答がコードにより関連性の高いものになります。「#package.jsonの改善点を提案してくれますか？」や「#devcontainer.jsonに拡張機能を追加するにはどうすればよいですか？」などの質問をすることができます。

個々のファイルを手動で追加する代わりに、`#codebase`を使用して、VS Codeにコードベースから適切なファイルを自動的に検索させることができます。これは、質問に関連するファイルがわからない場合に役立ちます。

![Attach contextボタンとコンテキストクイックピックを表示しているチャットビューのスクリーンショット。](../images/prompt-engineering-guide/copilot-chat-view-attach-context.png)

[チャットでのコンテキストの使用](/docs/copilot/chat/copilot-chat-context.md)について詳しくはこちらをご覧ください。

### 具体的かつシンプルにする

チャットに何かを依頼するときは、依頼内容を具体的にし、大きなタスクを個別の小さなタスクに分割してください。たとえば、TypeScriptとPugを使用し、MongoDBデータベースからデータを取得する製品ページを持つExpressアプリを作成するようにチャットに依頼しないでください。代わりに、まずTypeScriptとPugを使用してExpressアプリを作成するように依頼します。次に、製品ページを追加するように依頼し、最後にデータベースから顧客データを取得するように依頼します。

チャットに特定のタスクを依頼するときは、使用したい入力、出力、API、またはフレームワークについて具体的に指定してください。プロンプトが具体的であればあるほど、結果は良くなります。たとえば、「データベースから製品データを読み取る」ではなく、「カテゴリ別にすべての製品を読み取り、JSON形式でデータを返し、Mongooseライブラリを使用する」とします。

### ソリューションを反復する

チャットに助けを求める際、最初の応答に縛られることはありません。反復してチャットにプロンプトを出し、ソリューションを改善できます。チャットには、生成されたコードのコンテキストと現在の会話の両方があります。
フィボナッチ数を計算する関数を作成するためにインラインチャットを使用した例を次に示します。

![フィボナッチ数を計算する関数に対するAIからの最初の応答](../images/prompt-engineering-guide/fibonacci-first.png)

再帰を使用しないソリューションの方が良いかもしれません。

![再帰を使用しないようにAIに依頼した結果](../images/prompt-engineering-guide/fibonacci-second.png)

コーディング規約に従うように、または変数名を改善するようにAIに依頼することもできます。

![より良い変数名を使用するようにAIに依頼した結果](../images/prompt-engineering-guide/fibonacci-third.png)

結果をすでに受け入れた場合でも、後でいつでもAIにコードの反復を依頼できます。
